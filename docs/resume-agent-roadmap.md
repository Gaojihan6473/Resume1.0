# Resume Agent 总路线图（P0—P2）

> 文档状态：规划基线
> 适用分支：`agent-v2`
> 更新日期：2026-08-22
> 详细文档：[P0 MVP PRD](./resume-agent-p0-prd.md) · [P1 PRD](./resume-agent-p1-prd.md) · [P2 PRD](./resume-agent-p2-prd.md)

## 1. 文档目的

本文是 Resume Agent 产品与研发总目录，用于统一以下问题：

1. 产品为什么要从现有 JD Analysis Workflow 演进为 Agent。
2. 全局 Agent、左侧 `JD分析` Tab、右侧边栏和现有页面如何协同。
3. 简历 X、岗位 Y、经历素材 E 之间的业务关系。
4. P0、P1、P2 分别解决什么问题、交付什么结果、明确不做什么。
5. LLM、规划、工具调用、短期记忆、长期记忆如何分阶段建设。
6. 如何在 P0 尽量不修改现有数据结构和稳定逻辑。

本文只做总览，准确的交互、状态、验收和技术约束以各阶段 PRD 为准。

---

## 2. 产品定位

### 2.1 一句话定义

> 一个以用户真实职业经历为证据，能够理解岗位目标、调用求职工具、规划并生成可审核定制简历的受控型求职 Agent。

### 2.2 用户价值

当前产品主要交付“JD 分析和修改建议”。Resume Agent 的目标是交付“岗位专属简历任务结果”：

- 明确用了哪份简历、哪个岗位和哪些约束。
- 能解释选择、修改和舍弃内容的原因。
- 所有可应用内容都能追溯到真实简历或经历证据。
- 用户审核后创建新版本，不覆盖基础简历。
- 后续逐步支持岗位推荐、简历选择、经历组合和投递反馈学习。

### 2.3 非目标

以下方向不属于当前路线图的核心：

- 通用闲聊助手。
- 自动海投和自动提交申请。
- 未经用户批准覆盖简历。
- 以关键词堆砌换取虚假 ATS 分数。
- 一开始就构建多 Agent 系统。
- 展示模型 Chain of Thought。

## 3. 核心业务模型：E、X、Y

### 3.1 对象定义

- `E（Experience）`：实习、项目、bullet、技能、作品、成果指标等真实经历素材。
- `X（Resume）`：一份完整简历或简历版本，是若干 E 的组合与表达。
- `Y（Job）`：一个岗位及其 JD，在现有系统中主要对应 Application。

P0 不新建经历库，暂时从当前 X 中提取可用 E；P1 再把 E 建设为独立长期资产。

### 3.2 X × Y 业务矩阵

| 关系 | 用户问题 | 产品任务 | 主要承载页面 | 优先级 |
|---|---|---|---|---|
| `1X → 1Y` | 这份简历针对这个岗位怎么改？ | 定岗分析、证据匹配、修改审核、生成 X′ | 简历编辑器：左侧 JD Tab + 中间预览 + 右侧栏 | P0 |
| `1X → nY` | 这份简历适合投哪些岗位？ | 已保存岗位匹配、排序、解释与收敛 | 简历编辑器右侧栏 | P1 |
| `nX → 1Y` | 这个岗位应该用哪份简历？ | 已有简历选择、比较和推荐基础版 | 岗位详情/岗位卡 | P1 |
| `nE → 1Y → X′` | 应该从全部真实经历中组合什么内容？ | 经历检索、排序、组装、校验 | 经历库 + Agent 工作台 | P1 |
| `nX → nY` | 多份简历和多个岗位如何分配？ | 投递策略、版本分配和效果学习 | 首页/数据面板/Agent | P2 |

### 3.3 业务闭环

```text
从简历出发：1X → nY → 选择一个 Y → 1X → 1Y → X′

从岗位出发：nX → 1Y → 选择基础 X → 1X → 1Y → X′

完整经历模式：nE → 1Y → X′ → 关联投递 → 获取结果反馈
```

## 4. 总体产品架构

推荐方案由四层组成，不以单一浮窗或单一右栏替代现有产品。

### 4.1 全局 Agent 层

作用：理解目标、识别 X/Y 关系、补齐上下文、创建任务、展示跨页面状态并调度用户进入正确工作台。

交互形态采用渐进展开的全局 Agent Dock，而不是常驻的大输入框或通用聊天窗：

```text
紧凑悬浮身份卡
→ 点击展开底部 Agent Dock
→ 在 Dock 内确认/切换简历 X 和岗位 Y
→ 输入可选的自然语言要求
→ 执行中变为进度 Dock
→ 完成后变为“待审核”任务胶囊并打开右侧工作台
```

P0 的 Dock 以结构化 X/Y 上下文为主、自然语言为辅。点击 X 或 Y 可向上展开下拉列表；选择结果与当前简历、左侧 `JD分析` Tab 双向同步。Dock 负责启动和调度，不承载完整结果。

P0 只支持 `1X → 1Y`；P1 扩展到 `1X → nY` 和 `nX → 1Y`；P2 再支持跨任务策略。

### 4.2 左侧 1/3：输入和任务配置层

现有左侧不是纯简历编辑区，而是：

```text
[简历编辑] [JD分析]
```

- `简历编辑`：编辑当前 X。
- `JD分析`：选择或输入 Y，查看历史，配置任务并发起 Workflow/Agent。

P0 保留 Tab 名称和原有快速分析能力，在 `JD分析` 内增量加入 Agent 定岗任务配置；不另建一套重复的岗位输入页。

### 4.3 中间：简历工件层

作用：展示当前 X、Agent 草稿 X′、Diff、高亮和 A4 版面结果。

P0 必须隔离基础简历和 Agent 草稿；P1 增加原版/草稿/Diff 切换及自动版面检查；P2 增加多版本策略视图。

### 4.4 右侧：结果解释与人工控制层

作用：显示 Agent 阶段、方案、证据、风险、Patch 审核和交付动作。

右侧栏不是孤立入口，也不是通用聊天窗。它消费左侧 JD Tab/全局 Agent 创建的任务，并与中间预览联动。

## 5. Agent 能力架构总览

### 5.1 P0：单 Agent、受限工具、任务内记忆

```text
用户目标
  ↓
单 Agent Planner/Executor
  ↓ 动态选择
只读工具：读取当前简历、读取岗位、检索证据、解析建议锚点
  ↓
校验工具：Patch 锚点校验、事实风险校验、结构校验
  ↓
生成 AgentProposal
  ↓
用户审核
  ↓
确定性程序创建新简历并关联岗位
```

- LLM：复用现有 DeepSeek 能力。
- 规划：单次任务内生成结构化计划，并根据工具观察决定下一步。
- 工具：只读和校验为主；模型不直接调用数据库写工具。
- 短期记忆：活动任务上下文、计划、工具事件、草稿和审核状态。
- 长期记忆：复用现有 Resume、Application 和 JD Analysis History；不新建记忆表。
- 停止条件：达到证据/格式要求，或达到调用、时间、Token、修订轮次上限。

### 5.2 P1：多对象工具和持久化任务

- 增加读取多岗位、多简历和经历库工具。
- 增加经历检索、排序、简历选择和版面检查工具。
- 引入持久化 Agent Run/Step/Approval 数据。
- 增加用户偏好和事实确认记忆。
- 支持任务恢复、版本回滚和有限自动修订。

### 5.3 P2：反馈学习和跨任务策略

- 增加投递结果、版本效果和用户决策记忆。
- 支持 nX/nY 组合策略、主动提醒和后台多任务。
- 扩展到求职信、面试准备和作品集等工件。
- 保持单 Agent 优先；只有真实证明单 Agent 无法满足时再评估多 Agent。

## 6. P0—P2 路线图

| 阶段 | 核心目标 | 核心关系 | 用户交付物 | 数据结构策略 |
|---|---|---|---|---|
| P0 | 完成可用的定岗简历 MVP | `1X → 1Y → X′` | 有证据、可审核的新简历版本 | 不迁移数据库；不改 ResumeData schema；复用 JSONB 历史 |
| P1 | 从单次优化升级为多对象选择和经历组合 | `1X → nY`、`nX → 1Y`、`nE → 1Y → X′` | 岗位排序、简历推荐、经历库生成 | 允许新增 Agent/Experience/Version 表，不破坏旧表 |
| P2 | 形成求职策略和反馈闭环 | `nX → nY` | 个性化投递策略与多种求职工件 | 建立长期记忆、反馈和任务队列 |

### 6.1 P0 主要需求

1. 全局 Agent 悬浮身份卡与可展开 Dock，支持 X/Y 下拉选择和单任务启动。
2. 左侧 `JD分析` Tab 增加 Agent 定岗配置，同时保留快速分析。
3. 新增服务端单 Agent 编排端点。
4. 实现 5 个以内的受控工具和有限循环。
5. 右侧栏增加执行、审核、完成和失败状态。
6. 建立隔离的 Agent 草稿，不污染基础简历 Store。
7. 复用现有建议定位、应用/撤销、简历创建、岗位关联和历史记录。
8. 用户确认后创建 X′，不覆盖 X。

详细内容见 [P0 MVP PRD](./resume-agent-p0-prd.md)。

### 6.2 P1 主要需求

1. 全页面上下文入口和任务历史。
2. 当前简历匹配多个已保存岗位。
3. 当前岗位推荐最合适的已有简历。
4. 完整经历库与证据确认。
5. 基于经历库组合 X′。
6. 服务端持久化 Agent Run、步骤和审批。
7. 版面感知修订和版本回滚。
8. 用户偏好记忆和系统 Eval。

详细内容见 [P1 PRD](./resume-agent-p1-prd.md)。

### 6.3 P2 主要需求

1. 多简历、多岗位投递策略。
2. 投递结果反馈学习。
3. 主动式 Agent 和机会提醒。
4. 多任务队列、后台执行和通知。
5. 求职信、面试、作品集等工件。
6. 更自然的语音、拖拽和生成式 UI。
7. 长期策略记忆、成本治理和实验平台。

详细内容见 [P2 PRD](./resume-agent-p2-prd.md)。

## 7. 阶段门槛

### P0 → P1

满足以下条件后才进入 P1：

- 真实测试用户可以完成 `1X → 1Y → X′`。
- Agent 不会覆盖基础简历。
- 所有自动可应用 Patch 都有可定位原文。
- 失败任务可取消和安全重试。
- 已建立固定回归案例并记录成功率、延迟和成本。
- 证明用户确实需要在多岗位/多简历间选择，而非只需要更好的单次分析。

### P1 → P2

- 经历库有足够真实数据和使用频率。
- 多对象匹配结果被用户实际采用。
- 投递、版本和结果之间有稳定关联。
- 长期记忆数据获得明确授权和可解释用途。
- P1 的任务成功率、恢复能力、权限与成本达到可控水平。

## 8. 总体指标

### 产品指标

- 定岗任务启动率。
- 从任务启动到创建 X′ 的完成率。
- Agent 建议接受、编辑后接受和拒绝率。
- 单次定岗任务耗时。
- 新版本被导出或绑定岗位的比例。
- 用户回滚率和基础简历误覆盖率。

### Agent 指标

- 工具选择正确率。
- Patch 锚点成功率。
- 证据覆盖率。
- 无证据内容拦截率。
- 任务成功率、超时率、重试率。
- 单次成功任务的模型成本和延迟。

### 业务指标（P1/P2）

- 岗位推荐被选中率。
- 推荐简历被采用率。
- 经历库素材复用率。
- 定岗版本与面试结果的相关性。

## 9. 关键原则

1. **业务关系优先于 Agent 形态**：先判断 X/Y 关系，再决定页面和工具。
2. **全局入口不等于全局聊天**：Agent Dock 负责调度，业务工作台负责结果。
3. **左侧、预览、右侧是一个完整闭环**：输入在左、工件在中、解释和批准在右。
4. **能确定完成的部分继续用程序**：CRUD、Patch 应用、权限和导出不交给模型自由执行。
5. **P0 新增优先、改造谨慎**：不迁移数据库、不改变 ResumeData、不重写现有 Workflow。
6. **草稿必须隔离**：最小改造不能以覆盖基础简历为代价。
7. **单 Agent 优先**：规划、工具、观察、修订闭环成立后再讨论复杂编排。
8. **所有写入需人工批准**：模型只提出方案，确定性程序执行最终写入。
